What is a CSP?

A CSP uses a factored representation — each state is a set of variables with values, not an atomic black box. This structure enables powerful domain-independent inference techniques unavailable to ordinary search.

CSP = (X, D, C)

X = {X₁, X₂, …, Xₙ}   // variables
D = {D₁, D₂, …, Dₙ}   // domains, one per variable
C = {C₁, C₂, …, Cₘ}   // constraints

Each Cⱼ = ⟨scope, rel⟩
  scope: tuple of variables in the constraint
  rel: allowable value combinations
Solution: A consistent (no constraint violated) and complete (every variable assigned) assignment. Solving a CSP is NP-complete in general — but structure can be exploited to solve efficiently.

Constraint Types

Unary

Restricts a single variable. Example: SA ≠ Green.

⟨{X}, X ≠ Green⟩
Binary

Relates two variables. A binary CSP has only unary and binary constraints. Maps to graph edges.

⟨{SA, NSW}, SA ≠ NSW⟩
Global / Higher-Order

Involves an arbitrary number of variables. Alldiff is the most common: all variables must differ.

Alldiff(X₁, X₂, … Xₙ)
Why Alldiff over binary constraints? Two reasons: (1) easier and less error-prone to specify, and (2) enables special-purpose inference algorithms that are more efficient than working with primitive binary constraints.
Preference constraints indicate which solutions are preferred, not just which are allowed. CSPs with preferences become constrained optimization problems (COPs) — solved with optimization search. Linear programs are one class of COP.

Scheduling Constraints (Example)

Job scheduling adds two forms of constraints:

// Precedence: T₁ before T₂
T₁ + d₁ ≤ T₂

// Disjunctive: no overlap
(AxleF + 10 ≤ AxleB) OR
(AxleB + 10 ≤ AxleF)

Disjunctive constraints require one task to fully precede the other — they cannot overlap in time. With infinite domains, constraints must be implicit like this rather than explicit tuples.

The Key Advantage: Constraint Propagation

Atomic search can only expand nodes. A CSP algorithm has an additional move: constraint propagation — using constraints to reduce variable domains, which cascades reductions through the graph. This is what makes CSPs tractable in practice.

Local consistency: Each variable is a node, each binary constraint is an edge. Enforcing local consistency at each part of the graph eliminates inconsistent values globally — without exploring the full search tree.

Forward Checking vs. MAC

Forward Checking: After assigning Xi=v, look ahead and remove from neighbors' domains any value inconsistent with v. Simple, but only one step ahead — doesn't detect all inconsistencies.

Problem: FC can miss cases where two unassigned variables become mutually inconsistent even without a direct connection to the current assignment.

MAC (Maintaining Arc Consistency): After each assignment, runs AC-3 over the remaining arcs. Much more powerful — propagates reductions across the entire constraint graph, not just immediate neighbors.

MAC catches all inconsistencies that FC misses. Combined with MRV, this is the standard approach for hard CSPs.

Backtracking Search — Key Properties

Backtracking exploits commutativity: CSPs are commutative — the order of assignment doesn't matter, so we only need to consider one variable at a time at each depth level. This collapses n! orderings into a single tree.

Single state representation: Unlike tree search which creates new state objects, backtracking keeps a single assignment and alters it — reversing changes on backtrack. Memory efficient.

Unlike uninformed search (which needs domain-specific heuristics), backtracking can be improved with domain-independent heuristics that exploit the factored CSP representation:

  • Which variable to assign next?
  • In what order to try its values?
  • What inference to run after each assignment?
  • When to backtrack, and how far?

Backjumping vs. Chronological Backtracking

Chronological backtracking always returns to the most recent decision. But the conflict may have been caused by a variable much further back — so chronological backtracking wastes time on irrelevant intermediate assignments.

Simple backjumping: Tracks each variable's conflict set — the assignments that caused it trouble. Jumps back to the most recent member of that set, skipping irrelevant variables in between.

But: Forward checking already detects everything backjumping would catch, so simple backjumping is redundant in FC search — you only need one or the other.
Conflict-directed backjumping (CBJ): Uses a deeper definition of conflict set — the set of preceding variables that caused the current variable and subsequent variables to have no consistent solution together. When backjumping, merges conflict sets:
conf(Xᵢ) ← conf(Xᵢ) ∪ conf(Xⱼ) − {Xᵢ}
Constraint learning / No-goods: When a conflict is found, record a no-good — the minimum set of variables and values that caused the failure. Add a new constraint forbidding this combination (or cache it). Over time this prunes the search space dramatically. One of the most important techniques in modern CSP solvers.

Variable Ordering — MRV (Minimum Remaining Values)

Choose the variable with the fewest legal values remaining in its domain. Also called the most constrained variable or fail-first heuristic.

Fail-first rationale: By picking the variable most likely to fail soon, we prune the search tree earlier rather than discovering the failure deeper in. This is purely domain-independent — works for any CSP.
Degree heuristic (tiebreaker): When MRV is tied, choose the variable with the most constraints on remaining unassigned variables. Reduces future branching factor.
MRV Example — Which Variable Next?
Combined power: MRV + forward checking work well together. FC tells us when a domain has been reduced, giving MRV accurate information about which variable is most constrained.

Value Ordering — Least Constraining Value (LCV)

Once a variable is selected, prefer the value that rules out the fewest choices for neighboring variables in the constraint graph.

Asymmetry of intent: For variable ordering (MRV), we want to fail fast. For value ordering (LCV), we want to succeed — we need only one solution, so try the most likely values first. These goals are not in conflict: MRV picks the hardest variable, LCV picks its easiest value.

Local Search for CSPs

Local search uses a complete-state formulation: start with all variables assigned (possibly violating constraints), then repair violations iteratively. Effective for many large CSPs where backtracking would be impractical.

Min-conflicts heuristic: When reassigning a variable, choose the value that results in the minimum number of conflicts with other variables. Surprisingly effective — can solve n-queens for n=10⁶ in roughly n steps.

Plateau Navigation Techniques

The min-conflicts landscape typically has plateaus — flat regions where all neighbors have equal conflict counts. Two techniques help escape:

Tabu search: Keep a small list of recently visited states. Forbid returning to those states. Forces exploration of new territory on the plateau.
Constraint weighting: Give each constraint a numeric weight (all start at 1). At each step, choose variable/value minimizing total weighted violated constraints. Then increment weights of currently-violated constraints.

Two benefits: (1) adds topography to plateaus, (2) learning — difficult constraints accumulate higher weights over time.

Why Graph Structure Matters

The topology of the constraint graph determines tractability. Independent subproblems can be solved separately, and tree-structured graphs can be solved in linear time.

Independence: Find connected components of the constraint graph. Solve each subproblem separately. If assignment Sᵢ solves CSPᵢ, then ⋃ Sᵢ solves the full CSP. Dividing a Boolean CSP with 100 variables into four subproblems: worst-case time drops from universe lifetime to under a second.

Tree-Structured CSPs — Linear Time

Any tree-structured CSP (constraint graph is a tree — any two variables connected by only one path) can be solved in O(nd²) time.

Algorithm (TREE-CSP-SOLVER):
1. Pick root variable
2. Topological sort the variables
3. For j = n down to 2:
   MAKE-ARC-CONSISTENT(
     PARENT(Xⱼ), Xⱼ)
4. Assign variables root → leaf
  (no backtracking needed)

Time: O(nd²)
Why no backtracking? After directional arc-consistency (DAC), every parent→child arc is arc-consistent. For any value chosen for the parent, a valid child value is guaranteed to exist.

Reducing to Trees

Two strategies for converting a general graph to a tree:

Cycle cutset conditioning: Find a subset S of variables (the cycle cutset) whose removal makes the graph a tree. Try all consistent assignments to S. For each, solve the resulting tree. Works in linear memory. Finding the minimum cutset is NP-hard, but good approximations exist.
Tree decomposition: Collapse groups of variables into "mega-nodes" so the resulting graph of mega-nodes is a tree. Solve with TREE-CSP-SOLVER on the decomposed graph.

Tree width w: one less than the size of the largest mega-node. CSPs with bounded tree width are solvable in O(nd^(w+1)) — polynomial time. Finding minimum tree width is NP-hard, but heuristics work well.

Tradeoff: Cutset conditioning favors tree decomposition in time but runs in linear memory. Tree decomposition is faster when tree width is small but requires memory exponential in w.
Symmetry breaking: Many CSPs have value symmetry — permuting the values of a solution gives another solution. Introducing a symmetry-breaking constraint (e.g., enforce a canonical ordering) reduces the search space by d! for d symmetric values.
