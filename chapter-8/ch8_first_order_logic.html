First-Order Logic

Russell & Norvig — Artificial Intelligence: A Modern Approach, 4th ed.

// Why First-Order Logic?

Propositional logic can only represent facts — it has no concept of objects, properties, or relationships. First-order logic (FOL) extends it with a richer ontology, enabling statements like "Every student who studies passes" rather than a separate proposition for every student.

Propositional Logic

  • Ontology: facts only
  • No objects, no relations
  • One proposition per ground truth
  • E.g. WumpusAlive, Stench12
  • Scales poorly with domain size

First-Order Logic

  • Ontology: objects, relations, functions
  • Variables quantified over domains
  • One rule covers infinite cases
  • E.g. ∀x Wumpus(x) ⇒ Smelly(x)
  • Semi-decidable but expressive

Different logics make different assumptions about the world and about what agents can know:

⚠ Both propositional and first-order logic struggle with vague propositions ("tall", "spicy") — a key limitation for domains like politics or cuisine.

// Syntax Elements

FOL syntax builds on propositional logic by adding terms (to represent objects) and quantifiers (to make general statements). Every well-formed formula (sentence) is either atomic or built from atomic sentences using connectives and quantifiers.

// Terms

A term denotes an object in the domain. There are three kinds:

  • Constant — names a specific object: John, 2, LHR
  • Variable — ranges over objects: x, y, s
  • Function — maps objects to an object: LeftLeg(John)
-- Terms Richard -- constant x -- variable Father(John) -- function applied to constant LeftLeg(x) -- function applied to variable

// Atomic Sentences

An atomic sentence asserts that a relation (predicate) holds between one or more terms. It is the simplest sentence that can be true or false.

-- Predicate(term, term, ...) Brother(Richard, John) Married(Father(Richard), Mother(John)) OnTable(x) x = y -- equality is built-in

An atomic sentence is true when the named relation holds between the named objects in the model.

// Complex Sentences (Connectives)

The same connectives from propositional logic apply:

¬ Wumpus(x) -- negation Rich(x) ∧ Famous(x) -- conjunction Killed(John, Wumpus) ∨ Alive(Wumpus) -- disjunction Stench(s) ⇒ Adjacent(s, Home(Wumpus)) -- implication Sibling(A, B) ⟺ Sibling(B, A) -- biconditional

// Models in FOL

A model (possible world) for FOL consists of:

  • A non-empty set of objects — the domain D
  • An interpretation mapping:
    • Each constant → an object in D
    • Each predicate → a relation (subset of Dn)
    • Each function → a function Dn → D

Unlike propositional logic, there are infinitely many possible FOL models even for small domains, because the mapping from symbols to domain objects can vary freely.

// Universal Quantifier ∀

"For all …" — asserts the sentence holds for every object in the domain.

∀x King(x) ⇒ Person(x) -- "Every king is a person." ∀x Crown(x) ⇒ OnHead(x, KingOf(Country(x))) -- "Every crown is on the head of the king of its country."

Common Pitfall

∀ is almost always paired with ⇒, not ∧. Why?

-- WRONG: ∀x King(x) ∧ Person(x) -- This claims everything in the domain is BOTH a king AND a person. -- CORRECT: ∀x King(x) ⇒ Person(x) -- "If something is a king, then it is a person." -- True even if there are no kings (vacuously true).

// Existential Quantifier ∃

"There exists …" — asserts the sentence holds for at least one object in the domain.

∃x Crown(x) ∧ OnHead(x, John) -- "There is a crown on John's head." ∃x Person(x) ∧ Loves(x, Mary) -- "Someone loves Mary."

Common Pitfall

∃ is almost always paired with ∧, not ⇒. Why?

-- WRONG: ∃x Crown(x) ⇒ OnHead(x, John) -- True even if no crowns exist (implication is vacuously true)! -- CORRECT: ∃x Crown(x) ∧ OnHead(x, John) -- Requires at least one crown that is actually on John's head.

// De Morgan's Laws for Quantifiers

The quantifiers are duals — each can be expressed in terms of the other via negation:

∀x P(x) ≡ ¬∃x ¬P(x) ∃x P(x) ≡ ¬∀x ¬P(x) ¬∀x P(x) ≡ ∃x ¬P(x) ¬∃x P(x) ≡ ∀x ¬P(x)

// Nested Quantifiers & Scope

Order matters when mixing quantifiers. Variables are bound by the innermost matching quantifier.

∀x ∃y Loves(x, y) -- "Everyone loves someone." (y can differ per x) ∃y ∀x Loves(x, y) -- "There is someone loved by everyone." (same y for all x) -- These are NOT equivalent!

// Equality

FOL includes a built-in predicate = for object identity, allowing unique existence assertions:

-- At least two crowns exist: ∃x ∃y Crown(x) ∧ Crown(y) ∧ x ≠ y -- Exactly one king: ∃x King(x) ∧ ∀y King(y) ⇒ y = x

// Example KB: Electronic Circuits

A worked example from the textbook — encoding a circuit domain in FOL:

-- Domain: terminals, gates, signals ∀g Gate(g) ∧ Type(g, AND) ⇒ Signal(Out(1,g)) = 1 ⟺ Signal(In(1,g))=1 ∧ Signal(In(2,g))=1 ∀g Gate(g) ∧ Type(g, OR) ⇒ Signal(Out(1,g)) = 1 ⟺ Signal(In(1,g))=1 ∨ Signal(In(2,g))=1 ∀g Gate(g) ∧ Type(g, NOT) ⇒ Signal(Out(1,g)) ≠ Signal(In(1,g)) -- Terminals connected ↔ same signal ∀t1 t2 Connected(t1,t2) ⇒ Signal(t1) = Signal(t2)
