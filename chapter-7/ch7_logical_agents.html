Knowledge-Based Agents

A KB agent uses explicit knowledge to reason rather than hard-coded reflexes. Its central data structure is a knowledge base — a set of sentences in a representation language.

Core Operations

Operation

TELL

Add a sentence to the KB — asserting something about the world from a percept or prior knowledge. When given without derivation, a sentence is called an axiom.

Operation

ASK

Query the KB for an answer. The answer must follow from what has been previously told. May involve extensive inference (deriving new sentences from old ones).

Concept

Inference

The process of deriving new sentences from existing KB sentences. Must preserve truth — answers returned by ASK must be logically entailed by the KB.

Key Inference Example (Entailment)

When the agent perceives [Nothing at 1,1] and [Breeze at 2,1], there are 2³ = 8 possible models for pits in {[1,2],[2,2],[3,1]}.
Result: In every KB-true model → no pit in [1,2]. So KB ⊨ ¬P₁,₂.
But some KB-true models have pit in [2,2] and some don't → KB ⊭ ¬P₂,₂. Cannot conclude either way.

KB ⊨ α   iff   M(KB) ⊆ M(α)
// Every model satisfying KB also satisfies α

Syntax & Semantics

Syntax defines what sentences are legal. Semantics defines what they mean — i.e., their truth value in each possible world (model).

Connectives (Precedence: high → low)

Highest precedence

¬   Negation (NOT)

¬P is true iff P is false. A literal is a positive or negated atomic sentence.

¬W₁,₃   // "Wumpus not in [1,3]"
2nd

∧   Conjunction (AND)

P ∧ Q is true iff both P and Q are true. Parts called conjuncts.

W₁,₃ ∧ P₃,₁
3rd

∨   Disjunction (OR)

P ∨ Q is true iff at least one of P, Q is true. Parts called disjuncts.

(W₁,₃ ∧ P₃,₁) ∨ W₂,₂
4th

⇒   Implication (IF-THEN)

P ⇒ Q is false only when P is true and Q is false. Also written ⊃ or →. Antecedent (premise) ⇒ Consequent (conclusion).

(W₁,₃ ∧ P₃,₁) ⇒ ¬W₂,₂
Lowest precedence

⇔   Biconditional (IFF)

P ⇔ Q is true iff P and Q have the same truth value. "If and only if."

W₁,₃ ⇔ ¬W₂,₂

Key Semantic Concepts

Concept

Model

A precise "possible world" — an assignment of true/false to every proposition symbol. E.g. m₁ = {P₁,₂ = F, P₂,₂ = F, P₃,₁ = T}.

Concept

Validity (Tautology)

A sentence true in all models. E.g. P ∨ ¬P. Every valid sentence is logically equivalent to True.

(α ⊨ β)   iff   (α ⇒ β) is valid
Concept

Satisfiability

A sentence true in some model. SAT is NP-complete (first problem proved NP-complete). CSPs are really satisfiability problems.

α ⊨ β   iff   (α ∧ ¬β) is unsatisfiable
Concept

Logical Equivalence

α ≡ β if true in exactly the same models. Equivalent to α ⊨ β and β ⊨ α. Not the same as ⇔ (which is a connective inside a sentence).

Key Equivalences (De Morgan & Friends)

¬(¬α) ≡ α                      // Double negation
¬(α ∧ β) ≡ (¬α ∨ ¬β)           // De Morgan
¬(α ∨ β) ≡ (¬α ∧ ¬β)           // De Morgan
α ⇒ β  ≡ ¬α ∨ β               // Implication elimination
α ⇔ β  ≡ (α ⇒ β) ∧ (β ⇒ α)   // Biconditional elimination

Inference

Entailment is the semantic notion (needle in haystack). Inference is how we find it (syntactic process). Key properties: soundness and completeness.

Soundness vs Completeness

Property

Sound (Truth-Preserving)

Derives only entailed sentences. An unsound procedure "makes things up" — announces nonexistent needles. Model checking is sound.

Property

Complete

Can derive any entailed sentence. An incomplete procedure misses some needles that are actually in the haystack.

Property

Monotonicity

Adding information to KB can only increase the set of entailed sentences — never retract them.
If KB ⊨ α, then KB ∧ β ⊨ α

Model Checking vs Theorem Proving

Method

Model Checking (TT-Entails?)

Enumerate all possible models, verify α is true in every KB-true model. Exponential worst case. M(KB) ⊆ M(α).

Method

Theorem Proving

Apply inference rules directly to sentences — build a proof chain. Can ignore irrelevant propositions. Proof search uses standard search algorithms (BFS, DFS, A*).

KB ⊢ᵢ α   // "α is derived from KB by inference algorithm i"

Forward & Backward Chaining

Apply only to Horn clauses (definite clauses: exactly one positive literal). Linear time in KB size.

Forward Chaining (Data-Driven)

Start from known facts. Fire any rule whose premises are all satisfied. Add conclusion to known facts. Repeat until query derived or no new facts.

  • Sound & Complete for Horn KBs
  • Direction: data → goal
  • Basis for logic programming
  • May derive irrelevant facts
Backward Chaining (Goal-Directed)

Start from query q. Find rules whose conclusion is q. Prove each premise recursively. Succeed when all premises are known facts.

  • Sound & Complete for Horn KBs
  • Direction: goal → data
  • Often cheaper than forward (touches only relevant facts)
  • Used in Prolog-style reasoning

Resolution & CNF Conversion

Resolution is a single, complete inference rule for propositional logic. Requires sentences in Conjunctive Normal Form (CNF) — a conjunction of clauses (disjunctions of literals).

CNF Conversion — Step by Step

Example: convert B₁,₁ ⇔ (P₁,₂ ∨ P₂,₁). Click each step to expand the note.

1
Eliminate ⇔
(B₁,₁ ⇒ (P₁,₂ ∨ P₂,₁)) ∧ ((P₁,₂ ∨ P₂,₁) ⇒ B₁,₁)
Replace α ⇔ β with (α ⇒ β) ∧ (β ⇒ α).
2
Eliminate ⇒
(¬B₁,₁ ∨ P₁,₂ ∨ P₂,₁) ∧ (¬(P₁,₂ ∨ P₂,₁) ∨ B₁,₁)
Replace α ⇒ β with ¬α ∨ β. Applied to both implications.
3
Move ¬ Inward (De Morgan)
(¬B₁,₁ ∨ P₁,₂ ∨ P₂,₁) ∧ ((¬P₁,₂ ∧ ¬P₂,₁) ∨ B₁,₁)
¬(P₁,₂ ∨ P₂,₁) ≡ (¬P₁,₂ ∧ ¬P₂,₁) by De Morgan's law. ¬ must appear only in literals.
4
Distribute ∨ over ∧
(¬B₁,₁ ∨ P₁,₂ ∨ P₂,₁) ∧ (¬P₁,₂ ∨ B₁,₁) ∧ (¬P₂,₁ ∨ B₁,₁)
Distribute (α ∧ β) ∨ γ → (α ∨ γ) ∧ (β ∨ γ). Result is three clauses in CNF.

Clause Types

Type

Definite Clause

Disjunction of literals with exactly one positive. Can always be written as an implication (body ⇒ head). Basis for Horn clause reasoning.

(¬L₁,₁ ∨ ¬Breeze ∨ B₁,₁)
≡ (L₁,₁ ∧ Breeze) ⇒ B₁,₁
Type

Horn Clause

Disjunction with at most one positive literal. Definite clauses + goal clauses (no positives). Closed under resolution. Enables linear-time inference.

Type

k-CNF

CNF where each clause has at most k literals. 3-CNF (3-SAT) is NP-complete. 2-CNF is in P.

Resolution Refutation Demo

To prove KB ⊨ α: add ¬α to KB, convert all to CNF, resolve until empty clause (contradiction) → KB entails α. Example: KB = ¬B₁,₁, B₁,₁ ⇔ (P₁,₂ ∨ P₂,₁). Prove ¬P₁,₂.

Ground Resolution Theorem

If the resolution closure RC(S) of a set of clauses S does not contain the empty clause, then S is satisfiable. Contrapositive: if S is unsatisfiable, resolution will always derive the empty clause.
Termination guaranteed — only finitely many distinct clauses can be constructed from a finite set of symbols.

RC(S) contains □  ⟺  S is unsatisfiable  ⟺  KB ⊨ α (where ¬α was added to KB)

DPLL & WalkSAT

Practical SAT solvers go beyond naive model enumeration. DPLL (Davis–Putnam) uses smart pruning; WalkSAT uses local search — both handle large real-world instances.

DPLL — Three Key Improvements

1 · Early Termination

A clause is true if any literal is true — even with partial model. A clause is false only if all literals are assigned false. Prunes the search tree before assignment is complete.

2 · Pure Symbol Heuristic

A pure symbol appears with only one sign across all unresolved clauses. Assign it to make its literal true — this can never falsify any clause. Ignores clauses already known true.

(A ∨ ¬B), (¬B ∨ ¬C), (C ∨ A) → A is pure (only +), B is pure (only −), C is impure.

3 · Unit Clause Heuristic + Unit Propagation

A unit clause has only one unassigned literal (others are false under current model). That literal must be true → forced assignment. Cascade of forced assignments is unit propagation — resembles forward chaining. When CNF contains only definite clauses, DPLL essentially replicates forward chaining.

Additional DPLL Tricks (inherited from CSP/search)

Trick

Component Analysis

Identify independent sub-problems (disconnected subgraphs of variable interactions) and solve separately.

Trick

Variable & Value Ordering

Choose which variable to branch on and which value to try first (e.g., VSIDS — variable state independent decaying sum).

Trick

Intelligent Backtracking

Jump back to the cause of a conflict (conflict-driven clause learning — CDCL), not just one level.

Trick

Random Restarts

Periodically restart with a different random seed to escape bad search branches. Retains learned clauses.

Trick

Clever Indexing

Watch-literal indexing lets the solver quickly find unit clauses without scanning all clauses at each step.

WalkSAT

Local search for SAT. Start with a random assignment. Repeat: pick an unsatisfied clause, flip a symbol in it (random or min-break). Terminates when all satisfied or step limit reached. Incomplete — can miss solutions but fast in practice.

Problem Hardness & Phase Transition

Not all SAT instances are equal. Difficulty depends on the ratio of clauses to variables (for k-CNF):

Underconstrained

Few Clauses / Variables

Solutions densely distributed — any assignment is likely near a solution. Easy (e.g., n-queens for small n).

Overconstrained

Many Clauses / Variables

Constraints quickly lead to dead end or solution. Often no solution. Easy to show unsatisfiable.

Phase Transition

At Threshold Ratio rₖ

Hardest problems live here. The satisfiability threshold conjecture: probability of satisfiability jumps from ~1 to ~0 sharply at rₖ as n → ∞.

Complexity Summary

TT-Entails?: O(2ⁿ) SAT: NP-complete Horn KB inference: O(n) 3-SAT: NP-complete 2-SAT: polynomial #P: counting problems

SATPLAN & Temporal Reasoning

Logic can represent change over time using timestamped fluents and successor-state axioms. SATPLAN converts a planning problem into SAT and extracts a plan from a satisfying model.

The Frame Problem → Successor-State Axioms

Rather than axioms about actions (which suffer from the frame problem), write axioms about fluents — propositions that change over time. For each fluent F at time t+1, state exactly when it becomes true or stays true.

Fᵗ⁺¹  ⇔  ActionCauses(F)ᵗ  ∨  (Fᵗ ∧ ¬ActionCausesNot(F)ᵗ)
// F holds next time iff an action just caused it, or it held before and no action just eliminated it

Qualification problem: impossible to enumerate all preconditions that could prevent an action — no complete solution within logic. Designers must decide which details to model.

Caching: to avoid O(t) inference time at step t, cache (store) results of prior inference rather than re-deriving from scratch.

From the model, identify action variables assigned true → that sequence is the plan.

↓

Increment t

Try t = 1, 2, … up to Tmax. Guaranteed shortest plan. Cannot be used in partially observable environments.

SATPLAN Surprises & Fixes

Issue 1

Impossible Actions

Solver may include actions in the plan that have false premises (e.g., Grab when not at gold). Fix: add precondition axioms asserting actions can only be taken when preconditions hold.

Issue 2

Simultaneous Actions

Solver may assign multiple actions true at the same timestep. Fix: add action exclusion axioms — for every pair of actions (Aᵢᵗ, Aⱼᵗ), add ¬Aᵢᵗ ∨ ¬Aⱼᵗ.

Bonus

Debugging KB

SATPLAN reveals gaps in knowledge — if no plan is found, missing axioms are likely the cause. Good tool for KB verification.

SATPLAN KB = Init₀ ∧ SuccessorStateAxioms ∧ PreconditionAxioms ∧ ActionExclusionAxioms ∧ Goalₜ
